# Liderazgo técnico y mentoring

La vacante pide explícitamente "leading technical direction", "mentoring
engineers and maintaining high technical standards" y "collaborating with
Product, Design, and Engineering leaders". A diferencia de los demás temas,
esto no se estudia con documentación técnica sino preparando **ejemplos
concretos propios**, formato entrevista de comportamiento (behavioral).

## Objetivos

- Tener 3-5 historias reales (formato **STAR**: Situación, Tarea, Acción,
  Resultado) que muestren liderazgo técnico, no solo ejecución individual.
- Poder explicar una decisión de arquitectura que hayas tomado o
  influenciado, incluyendo el trade-off que descartaste y por qué.
- Poder describir cómo mentoreaste (formal o informalmente) a alguien más
  junior, o cómo elevaste el estándar técnico de un equipo (code review,
  buenas prácticas, documentación).
- Poder hablar de un desacuerdo técnico con un par o líder y cómo se
  resolvió (sin quedar como "el que siempre tiene razón" ni "el que cede
  siempre").

## Subtemas

1. Formato STAR para entrevistas de comportamiento
2. Ejemplos de decisión de arquitectura (usar los diagramas de
   `../02-sistemas-distribuidos-hexagonal/` como material de apoyo)
3. Ejemplos de mentoring / elevar el estándar técnico del equipo
4. Ejemplos de colaboración cross-funcional (Product/Design) — momentos
   donde tradujiste una necesidad de negocio a una decisión técnica

## Cómo preparar esto acá

A diferencia de los otros temas, para este no hace falta "examen" en el
sentido tradicional. Mejor pedime: *"Hacé de entrevistador y hacéme 3
preguntas de comportamiento tipo liderazgo técnico"* — te doy la pregunta,
respondés con una historia real, y te doy feedback sobre si la estructura
STAR está clara y si el resultado muestra impacto medible.
