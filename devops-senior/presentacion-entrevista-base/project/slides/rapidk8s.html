Questions the recruiter sent: Kubernetes

Control plane components

kube-apiserver, etcd, kube-scheduler, kube-controller-manager, cloud-controller-manager — only the API server talks to etcd

Worker node

kubelet, kube-proxy, container runtime (containerd); add-ons CoreDNS and the CNI plugin

What is a Pod?

Smallest deployable unit; containers share the network namespace and volumes; ephemeral, so Deployments manage it

How to create a Pod

kubectl run (imperative) or kubectl apply -f pod.yaml with apiVersion, kind, metadata, spec

Purpose of kubectl

The CLI client of the kube-apiserver, authenticated with the kubeconfig file

Control plane, out loud: “The control plane has five components. The kube-apiserver is the front door — everything, including kubectl, talks to it over REST, and it handles authentication, RBAC (Role-Based Access Control) and admission. etcd is the key-value store, the single source of truth; only the API server talks to it. The kube-scheduler assigns Pods to nodes. The kube-controller-manager runs the reconciliation loops. And the cloud-controller-manager integrates with the cloud: load balancers, volumes, nodes. In AKS, EKS or GKE the provider manages the control plane for you.” Pod: “The smallest deployable unit: one or more containers sharing the same IP and volumes. Pods are ephemeral — if one dies it’s replaced, not repaired — so in production we use Deployments, StatefulSets or DaemonSets, and a Service in front.” ES: #4 (control plane) salió flojo en PayU — es la #1 para memorizar. Pronunciación: kubectl = "kube-control" o "kube-C-T-L".
