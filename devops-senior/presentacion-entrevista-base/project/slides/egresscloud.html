Follow-up answer: “The idea is the same in every cloud, only the names change. In AWS it’s a NAT Gateway plus an Internet Gateway. In AKS you choose the outboundType: a load balancer by default, a managed NAT Gateway, or userDefinedRouting to send everything through Azure Firewall, where you can filter by FQDN (Fully Qualified Domain Name). In GKE with private nodes it’s Cloud NAT with a Cloud Router. Inside the cluster I control egress with NetworkPolicies — a default-deny egress policy plus explicit allows — and, with a service mesh, an Istio egress gateway. The classic mistake is a default-deny that also blocks DNS on port 53, so nothing resolves.” ES: Si te preguntan "¿cómo le doy una IP fija de salida a un partner?": la Elastic IP del NAT Gateway (AWS), la IP pública del NAT Gateway o del Azure Firewall (Azure), o IPs estáticas en Cloud NAT (GCP).
