Disk full, but du shows little

Deleted files still open by a process: lsof +L1. Then inodes (df -i) and files hidden under a mount

“Too many open files”

File descriptor limit: a leak or a low limit. ulimit -n, /proc/<pid>/limits, LimitNOFILE in systemd

Disk full, out loud: “The classic cause is files that were deleted but are still held open by a process — like a log deleted while the app keeps writing. du walks the directory tree so it doesn’t see them, but df still counts the blocks. I confirm with lsof +L1, then restart or reload the process, or truncate through /proc/pid/fd. Other causes: inode exhaustion, checked with df -i, and data hidden under a mount point.” Too many open files: “The process hit its file descriptor limit — sockets count as files too. First I check if it’s a leak: if ls /proc/pid/fd | wc -l keeps growing, it’s a code fix. If it’s real load, I raise the limit at the right layer: LimitNOFILE for a systemd service, limits.conf for user sessions, fs.file-max system-wide.” ES: Trampa común: cambiar limits.conf y que no surta efecto porque el servicio corre con systemd (necesita LimitNOFILE).
