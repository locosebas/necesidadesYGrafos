Question · Kubernetes networking

How does a Pod reach the internet?

01

Pod

Private IP; CoreDNS resolves the name

02

Node

CNI applies SNAT (masquerade) to the node IP

03

Route table

Private subnet: 0.0.0.0/0 → NAT

04

NAT Gateway

Public subnet; swaps to its Elastic IP

05

Internet Gateway

Attached to the VPC

06

Internet

Sees only the Elastic IP

Key idea: the Pod never gets a public IP. Its private address is translated twice — SNAT to the node, then NAT to the Elastic IP — and replies come back through connection tracking.

Inbound traffic is a different path: Service type LoadBalancer or an Ingress controller.

Model answer: “A Pod only has a private IP, so going out to the internet is a chain of translations. First, DNS: the Pod asks CoreDNS, which forwards external names to the VPC resolver. Then the packet leaves the Pod’s network namespace through a veth pair into the node, and the CNI (Container Network Interface) plugin — with iptables or eBPF rules — applies SNAT, masquerading the Pod IP as the node IP. The nodes live in a private subnet, whose route table sends 0.0.0.0/0 to a NAT Gateway in a public subnet. The NAT Gateway translates again to its Elastic IP and sends the traffic through the Internet Gateway. The destination only sees the Elastic IP — which is useful, because partners can allowlist one fixed IP.” Detail for a follow-up: on EKS with the AWS VPC CNI, Pods get real VPC IPs; by default the CNI still SNATs traffic leaving the VPC to the node’s primary IP (AWS_VPC_K8S_CNI_EXTERNALSNAT=false). If you set it to true, the NAT Gateway sees the Pod IP directly. ES: Frase clave: "two translations: SNAT at the node, NAT at the NAT Gateway". Primero DNS, después ruta, después NAT.
